# 校務資訊系統

## 1. 專案介紹

本專案以校園常見的教務與學務流程為主題，實作整合學生、教師與管理員三種角色的校務資訊系統。透過選課、成績登錄、申請審核與帳號管理等功能，呈現前後端整合、資料庫設計及角色權限控管的應用。

## 2. 主要功能

| 角色 | 功能 |
| --- | --- |
| 學生 | 加退選、選課結果與課表查詢、停修、通識初選、成績與期中預警查詢、缺曠與獎懲查詢、兵役申請、教學評量及問卷填寫 |
| 教師 | 授課課程與修課名單查詢、成績與期中預警登錄、缺曠與獎懲登錄、學生申請審核、教學評量統計及課程問卷管理 |
| 管理員 | 學生與教師帳號新增、查詢、編輯及密碼重設，設定加退選開放年級，以及停修、通識初選、期中預警與學期成績查詢開關 |

學生與教師皆可查詢課程資料、教師課表及教室課表。加選時會檢查名額、重複選課與時段衝突。

## 3. 技術架構

- **程式語言**：TypeScript、SQL、CSS。
- **前後端框架**：React 19、React Router 7，使用伺服器端渲染（SSR），並透過 loader 與 action 處理資料查詢及表單提交。
- **介面設計**：Material UI 9 與 Emotion，採藍灰淺色主題，共用角色導覽、表單、表格與狀態元件。
- **執行與建置工具**：Node.js 24 以上、Vite 7。
- **資料庫**：SQLite，使用 Node.js 內建的 `node:sqlite` 存取資料，以 SQL migration 管理資料表結構。
- **權限管理**：依學生、教師與管理員身分控管資料與功能的存取範圍。

## 4. 系統流程

管理員建立師生帳號並設定各項校務功能的開放狀態；學生進行選課、資料查詢與申請；教師則處理授課資料、成績登錄及申請審核，串起不同角色之間的校務流程。

## 5. 實作重點

- **角色權限區分**：各角色具有不同的功能選單與資料存取範圍。
- **選課規則處理**：加選時檢查開放年級、課程名額、重複選課及衝堂情況。
- **校務資料整合**：串接選課、成績、出缺勤、獎懲及申請紀錄。
- **申請流程設計**：通識初選經教師核准後正式加選，停修送出後立即生效並留下紀錄。

## 6. 介面結構

`app/theme.ts` 統一色彩、字體與元件密度；`app/components/app-shell.tsx` 提供角色導覽，`app/components/ui.tsx` 封裝保留原生表單行為的 Material UI 元件。課表保留星期與節次矩陣，專用排版集中在 `app/app.css`。

SSR 使用 Emotion 的串流樣式輸出，每次伺服器請求建立獨立快取；客戶端使用相同快取 key 接續樣式。維持 React Router 原有串流、回應狀態與標頭處理。樣式選擇器以元素類型與類別為主，避免依賴會受內嵌樣式標籤影響的 `:nth-child`。
