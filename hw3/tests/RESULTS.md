## 發現與修正

1. **兩格間受阻無法繞路：**原本必須先走完區段才能重新規劃，可能被前方行人卡住。允許先檢查身體與路徑安全，再退回上一個路點繞行；固定行人案例及四個穿越情境均通過。
2. **候位漏掉其他方案：**原本先截取前五個方案再排除拒絕紀錄。改為搜尋時排除，並繼續搜尋其他組合；候位重新接待案例通過。
3. **模型誤把容量不足記成歧義：**初次 18 個真實情境中，拒絕分桌情境有 2 次將「八位不分桌」記入特殊條件。補明模型只擷取需求、容量交由 Python 判斷，完整重跑後 18／18 通過。失敗樣本保存在 `observed-model-failures.json`，未放寬期望欄位。
4. **持續受阻提示閃回一般等待：**讓人工協助提示持續保留到恢復移動。
5. **新增速度欄位與停用按鈕配色：**補上 QDoubleSpinBox 樣式及確認按鈕停用樣式，重新查看原生畫面。
6. **原生 Qt 結束階段崩潰：**額外的直接腳本啟動／關閉檢查重現 SIGSEGV。`main.py` 改在 QApplication 仍存在時，先停止計時器，再依序處理視窗與模擬物件的延遲刪除。持久化的原生退出腳本正常結束碼 0，並加入獨立子程序回歸案例。
7. **HTTPError 資源釋放：**讀取錯誤內容後關閉回應，避免測試中的資源清理警告。

建立測試期間也修正了測試本身的環境問題：Qt 父子物件生命週期清理、缺少模組路徑的錯誤執行目錄，以及將障礙物點擊目標誤選到餐桌格。顧客到桌的檢查時間依實際路程及較慢速度延長，保留「入座前必須仍為保留」的斷言。

## 原生視窗涵蓋

- 真實 Ollama 接待與靠窗方案，確認後才保留並出發。
- 顧客停留時機器人保持原位置，恢復後繼續。
- 全域暫停／繼續、4 倍速、手動新增穿越行人，事件中出現減速／停止反應。
- 完成入座、機器人返回入口、下一組控制恢復。
- 第二組受阻持續 10 個模擬秒，保留桌位並提示人工協助。
- 移除障礙後完成原任務與返回，關閉視窗。

原生流程的按鈕先捲動到可見位置再操作。障礙情境透過地圖編輯的同一個 API 設定；一般 Qt 介面測試另有實際滑鼠點擊地圖新增／移除障礙的案例。
